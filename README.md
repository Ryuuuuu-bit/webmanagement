# TeachSchedule — ระบบตารางสอนอาจารย์ (รองรับหลาย site/สาขา)

ระบบบริหารจัดการตารางสอน การเช็คอิน-เช็คเอาต์ การลา การรับรองเวลา และแผนการสอนของอาจารย์ ออกแบบให้เป็นระบบปิด
ใช้งานภายในองค์กร (ผู้ดูแลระบบสร้างบัญชีให้เท่านั้น ไม่มีสมัครสมาชิกเอง) รองรับตั้งแต่องค์กรเดียวไซต์เดียว ไปจนถึงองค์กร
ที่มีอาจารย์หลายคนกระจายกันไปประจำหลาย site/สาขา — ทุกอย่างที่เป็น "ข้อมูลเฉพาะขององค์กร" (สาขาวิชา, รายวิชา, ห้อง/อาคาร,
ภาคเรียน, จุดเช็คอิน, โควต้าวันลา, นโยบายเช็คอิน, ใครประจำ site ไหน) จัดการได้เองผ่านหน้าเว็บ ไม่ต้องแก้โค้ดหรือ deploy ใหม่

> คู่มือสำหรับผู้ใช้ครั้งแรก (อาจารย์ + ผู้ดูแลระบบ) อยู่ที่ [`docs/`](./docs/) ทั้งแบบ Word และ PDF

## ฟีเจอร์หลัก

### บัญชีผู้ใช้และการเข้าสู่ระบบ
- **ระบบสมาชิกแบบปิด** — สิทธิ์ Admin / Member (อาจารย์) แยกกัน (NextAuth + role ใน JWT) ผู้ดูแลระบบสร้างบัญชีให้
  พร้อมสุ่มรหัสผ่านชั่วคราว (หมดอายุใน 7 วัน) บังคับตั้งรหัสผ่านใหม่ตอน login ครั้งแรก
- **เข้าสู่ระบบด้วย username + รหัสผ่าน** (รับอีเมลแทน username ได้ด้วย) — Admin ตั้ง username ตอนสร้างบัญชี
- **ไม่มี "ลืมรหัสผ่าน" แบบทำเอง** — อาจารย์ที่ลืมรหัสผ่านติดต่อผู้ดูแลระบบ ซึ่งกด "รีเซ็ตรหัสผ่าน" ในหน้าจัดการผู้ใช้
  ได้ทันที (ถ้าตั้งค่า Resend ไว้ Admin ยังเลือกส่ง "ลิงก์ตั้งรหัสผ่าน" ทางอีเมลให้แทนการบอกรหัสชั่วคราวได้)
- **Passkey / ไบโอเมตริก** — อาจารย์ลงทะเบียนอุปกรณ์ (ลายนิ้วมือ/Face ID ผ่าน WebAuthn) แล้วเข้าระบบได้โดยไม่ต้องพิมพ์
  รหัสผ่าน หน้า login จะเด้งขอสแกนอัตโนมัติในครั้งถัดไป
- **ลงทะเบียนอุปกรณ์ด้วย QR** — Admin สร้างลิงก์/QR ลงทะเบียน (อายุ 15 นาที ใช้ครั้งเดียว) อาจารย์สแกนบนมือถือ
  แล้วตั้งค่าไบโอเมตริกได้เลย ไม่ต้องรู้รหัสผ่านชั่วคราว
- **ความปลอดภัยบัญชี** — ล็อกชั่วคราวหลัง login ผิดหลายครั้ง (ต่อบัญชีและต่อ IP), นโยบายรหัสผ่าน (ความยาว, ไม่ซ้ำ
  รหัสยอดนิยม, ไม่ใช้อีเมล/username), ระงับบัญชีชั่วคราวแทนการลบ, "ออกจากระบบทุกอุปกรณ์", และ
  **ประวัติความปลอดภัย (Audit Log)** บันทึกทุกการเข้าสู่ระบบและการเปลี่ยนแปลงบัญชี
- **Admin จัดการข้อมูลอาจารย์ได้ครบ** — แก้ชื่อ/ชื่อผู้ใช้/อีเมล/ภาควิชา (ปุ่ม "แก้ไขข้อมูล"), เปลี่ยนบทบาทและ site ประจำ,
  และเปิดหน้า "ประวัติ / ลบรายการ" ของแต่ละคนเพื่อลบประวัติเช็คอิน คำขอลา คำขอรับรองเวลา หรือแผนการสอนที่ผิดพลาด
  ได้ทีละรายการหรือทั้งหมวด (ทุกการลบบันทึกในประวัติความปลอดภัย)
- **สองภาษา (TH/EN)** และ **Light/Dark mode** สลับได้ตั้งแต่หน้า login และทุกหน้าสาธารณะ

### ตารางสอนและงานประจำวัน
- **Dashboard** แยกมุมมอง Admin / อาจารย์ — ฝั่งอาจารย์กดเช็คอิน/เช็คเอาต์ได้จาก Dashboard โดยตรง (ใช้ขั้นตอนและนโยบายเดียวกับ
  หน้าเช็คอิน) พร้อมสถานะวันนี้และตารางสอนวันนี้
- **ตารางสอน** — ปฏิทินสไตล์ Microsoft Teams (มุมมองสัปดาห์ / วันทำงาน / วัน, กรองตามภาคเรียน, เส้นเวลาปัจจุบัน)
  เวลาแบบอิสระไม่ใช่คาบตายตัว อาจารย์ดูของตัวเอง/Admin จัดการได้ทั้งหมด พร้อมตรวจจับการจองซ้ำซ้อน (ทั้งอาจารย์และห้อง)
- **เช็คอิน/เช็คเอาต์ตามตำแหน่ง (GPS geofence)** — อาจารย์แต่ละคนมี **site ประจำ** (Admin กำหนดในหน้าจัดการผู้ใช้)
  เช็คอิน/เช็คเอาต์ต้องอยู่ในรัศมีของ site นั้นเท่านั้น ไม่มี site ประจำ = เช็คอินไม่ได้
- **ป้องกันการเช็คอินแทนกัน (anti buddy-punching)** — เปิด/ปิดได้จากหน้าเช็คอินของ Admin (นโยบายเช็คอิน):
  - ต้องยืนยันตัวตนด้วยไบโอเมตริกของอุปกรณ์ที่ลงทะเบียนไว้ (ไม่มีทางลัดด้วยรหัสผ่าน)
  - อุปกรณ์ใหม่ต้องรอ Admin อนุมัติก่อน (1 อุปกรณ์ต่อคน; ลงทะเบียนผ่าน QR อนุมัติอัตโนมัติ)
  - ถ่ายเซลฟี่ตอนเช็คอิน/เช็คเอาต์ เก็บเป็นหลักฐานตามจำนวนวันที่กำหนด (ค่าเริ่มต้น 90 วัน)
  - ตรวจจับ "มือถือเครื่องเดียวเช็คอินให้หลายคน" แล้วติดธง ⚠ ให้ Admin ตรวจสอบ
- **ยื่นคำขอลา** + workflow อนุมัติ (ประเภทการลาตาม พ.ร.บ. คุ้มครองแรงงาน) พร้อม **โควต้าวันลาต่อปีต่อประเภท**
  ที่ Admin ตั้งเองในข้อมูลหลัก — ขอเกินโควต้าได้แต่ระบบเตือนทั้งผู้ขอและผู้อนุมัติ
- **ขอรับรองเวลา** + workflow อนุมัติ — ใช้เมื่อลืมเช็คอิน/เช็คเอาต์ บันทึกแยกจากการเช็คอินผ่าน GPS จริง
- **แผนการสอน** — อาจารย์อัปโหลดไฟล์ (PDF/Word/PowerPoint สูงสุด 8 MB) ต่อวิชาที่สอน Admin ตรวจ/อนุมัติ/ส่งกลับแก้ไข
- **การแจ้งเตือนในแอป** — ทุกขั้นตอน "ขอ → อนุมัติ" มีแจ้งเตือน: อาจารย์ยื่นคำขอ (ลา/รับรองเวลา/แผนการสอน/อุปกรณ์ใหม่)
  → Admin ทุกคนได้รับแจ้ง, Admin อนุมัติ/ไม่อนุมัติ/ส่งกลับ → อาจารย์ได้รับแจ้ง รวมถึงเมื่อ Admin เพิ่ม/ลบคาบสอน
  เปลี่ยนสิทธิ์ หรือเปลี่ยน site ประจำให้ กระดิ่งพร้อมตัวเลขอยู่ในเมนู, หน้า "การแจ้งเตือน" รวมทุกรายการ และมีกล่องเด้ง
  ขึ้นเมื่อมีเรื่องใหม่ระหว่างเปิดแอปอยู่ ข้อความแสดงตามภาษาของคนอ่าน
- **ข้อมูลหลัก (Master Data)** — สาขาวิชา, รายวิชา, ห้อง/อาคาร (ผูกกับ site ได้), ภาคเรียน, โควต้าวันลา
- **จุดเช็คอิน-เช็คเอาต์ (`CampusLocation`)** — Admin เพิ่ม/แก้ไข/ลบ site ผ่านแผนที่ (Leaflet + OpenStreetMap)
  ค้นหาชื่อสถานที่ผ่าน Google Places API หรือคลิกปักหมุด/ลากปรับเอง
- **รายชื่ออาจารย์** — site ประจำ, ภาควิชา, สถานะเช็คอินวันนี้ ของทุกคนในหน้าเดียว
- **ใช้ได้ทั้ง PC และมือถือ** — เมนูแบบ drawer บนจอเล็ก ตารางข้อมูลเลื่อนได้ไม่บีบข้อความ ติดตั้งเป็น **PWA**
  บนหน้าจอโฮมได้ (มีคู่มือติดตั้งในหน้า login) session อยู่ได้ 90 วัน

## เริ่มต้นใช้งาน

**สิ่งที่ต้องมี:** Node.js 20+, PostgreSQL (local ผ่าน Docker หรือใช้ Railway/Neon ก็ได้)

```bash
npm install
cp .env.example .env      # แก้ DATABASE_URL, NEXTAUTH_SECRET (และค่าอื่นตามตารางด้านล่าง)
npx prisma db push        # สร้าง/อัปเดตตารางในฐานข้อมูล (โปรเจกต์นี้ไม่ใช้ migration history)
npm run prisma:seed       # ใส่ข้อมูลตัวอย่าง (อาจารย์/วิชา/ห้อง/ตารางสอน) — ไม่บังคับ
npm run dev
```

ตอน deploy จริง `npm start` จะรัน `prisma db push` → สคริปต์บำรุงรักษาใน `scripts/` (ทำงานเฉพาะเมื่อตั้งตัวแปรไว้)
→ `next start` ให้อัตโนมัติ

### การสร้างบัญชีผู้ใช้ (ระบบปิด — ไม่มีสมัครสมาชิกเอง)

ผู้ดูแลระบบ (role `ADMIN`) สร้างบัญชีให้อาจารย์แต่ละคนผ่าน **"จัดการผู้ใช้"** (`/admin/users`) โดยกรอกชื่อ, **username**,
อีเมล, ภาควิชา, **site ประจำ** และบทบาท จากนั้นเลือกวิธีส่งมอบบัญชีได้ 3 ทาง:

1. **รหัสผ่านชั่วคราว** — ระบบสุ่มให้ แสดงครั้งเดียว (หมดอายุ 7 วัน) ผู้ใช้ถูกบังคับตั้งรหัสใหม่ตอน login แรก
2. **QR/ลิงก์ลงทะเบียนอุปกรณ์** — อาจารย์สแกนบนมือถือ ตั้งค่าไบโอเมตริก แล้วใช้งานได้เลยไม่ต้องพิมพ์รหัสผ่าน (แนะนำ)
3. **ส่งลิงก์ตั้งรหัสผ่านทางอีเมล** — เฉพาะเมื่อตั้งค่า `RESEND_API_KEY` ไว้

ลืมรหัสผ่าน → Admin กด "รีเซ็ตรหัสผ่าน" หรือสร้าง QR ใหม่ในหน้าเดียวกัน (ไม่มีหน้าลืมรหัสผ่านสาธารณะ)

**site ประจำของอาจารย์แต่ละคนสำคัญมาก** — เป็นตัวกำหนดว่าเช็คอิน/เช็คเอาต์ของคนนั้นต้องอยู่ที่ไหน ต้องมีจุดเช็คอิน
(`/admin/locations`) อย่างน้อย 1 จุดก่อนถึงจะเลือกได้

> บัญชี/รหัสผ่านสำหรับทดสอบดูได้ใน `prisma/seed.ts` และ `scripts/seed-demo-users.mjs` (ไม่ commit ไว้ใน README
> เพราะ repo นี้อาจเป็น public) ก่อนใช้งานจริงให้เปลี่ยนรหัสผ่านและอีเมลตัวอย่างในนั้นด้วย

## ตั้งค่า Postgres แบบเร็วด้วย Docker

```bash
docker run --name teachschedule-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=webmanagement -p 5432:5432 -d postgres:16
```
แล้วใช้ `DATABASE_URL="postgresql://postgres:postgres@localhost:5432/webmanagement"` ใน `.env`

## ตัวแปรสภาพแวดล้อม (`.env`)

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `DATABASE_URL` | connection string ของ PostgreSQL |
| `NEXTAUTH_SECRET` | เข้ารหัส session/JWT — สร้างด้วย `openssl rand -base64 32` |
| `NEXTAUTH_URL` | URL ของเว็บ (เช่น `http://localhost:3000` ตอน dev) — ใช้เป็น origin ของ WebAuthn ด้วย |
| `TZ` | ควรตั้ง `Asia/Bangkok` บนเซิร์ฟเวอร์ ให้การคำนวณวัน/เวลาทั้งระบบเป็นเวลาไทย |
| `GOOGLE_PLACES_API_KEY` | ค้นหาชื่อสถานที่ในหน้าจุดเช็คอิน (`/admin/locations`) — ไม่มีก็ใช้งานได้ แค่ค้นหาชื่อไม่ได้ ต้องคลิกบนแผนที่แทน |
| `RESEND_API_KEY`, `EMAIL_FROM` | (ไม่บังคับ) เปิดปุ่ม "ส่งลิงก์ตั้งรหัสผ่านทางอีเมล" ให้ Admin ผ่าน [Resend](https://resend.com) — ไม่ตั้ง = ปุ่มไม่แสดง ระบบอื่นทำงานปกติ |
| `SEED_DEMO_USERS` | (บำรุงรักษา) ตั้งค่า token ใหม่หนึ่งครั้งเพื่อให้ `scripts/seed-demo-users.mjs` ล้างบัญชีอาจารย์ทั้งหมดแล้วสร้างบัญชีตัวอย่าง 3 คนตอน start — รันครั้งเดียวต่อ token แล้วเคลียร์ค่าออก |
| `DELETE_USERS`, `MAINTENANCE_TOKEN` | (บำรุงรักษา) ลบบัญชีตาม username ที่ระบุ (คั่นด้วยจุลภาค) ตอน start — ต้องตั้ง token ใหม่ทุกครั้ง แล้วเคลียร์ค่าออก |

## จุดที่ควรรู้ก่อนทดสอบเช็คอิน

1. หน้าเช็คอินขอสิทธิ์ตำแหน่ง (Geolocation) และกล้อง (ถ้าเปิดนโยบายเซลฟี่) จากเบราว์เซอร์ — ต้องเป็น **HTTPS**
   (หรือ `localhost`) ไม่งั้นทั้ง GPS, กล้อง และ WebAuthn จะใช้ไม่ได้
2. ต้องมีจุดเช็คอิน (`CampusLocation`) อย่างน้อย 1 จุดที่ `/admin/locations` — พิกัดที่ seed ไว้เป็นพิกัดสมมติ
3. **ต้องกำหนด site ประจำให้อาจารย์แต่ละคนที่ `/admin/users`** — ไม่มี site ประจำ = เช็คอินไม่ได้ (ดู `getExpectedSite`
   ใน `src/lib/geo.ts`)
4. ค่าเริ่มต้นของนโยบายเช็คอินคือ "เข้มสุด" (ต้องไบโอเมตริก + อุปกรณ์ต้องอนุมัติ + เซลฟี่) — ปรับได้ที่หน้าเช็คอินของ Admin
   ถ้าจะทดสอบบนเครื่องที่ไม่มีไบโอเมตริก ให้ปิด "ต้องยืนยันตัวตนด้วยไบโอเมตริก" ชั่วคราว
5. WebAuthn ผูกกับโดเมน — passkey ที่ลงทะเบียนบน `localhost` ใช้กับโดเมนจริงไม่ได้ (และกลับกัน)

```
prisma/schema.prisma        โมเดลข้อมูลทั้งหมด (User, Schedule, Attendance, LeaveRequest, LeaveQuota, TimeAttestation,
```

## ขั้นตอนถัดไปที่แนะนำ

1. ตั้งค่า `RESEND_API_KEY` ถ้าต้องการให้ Admin ส่งลิงก์ตั้งรหัสผ่านทางอีเมล
2. แจ้งเตือนแบบ push ตอนปิดแอป (Web Push + service worker) หรือส่งอีเมลซ้ำจากระบบแจ้งเตือน
3. รายงาน/Export ข้อมูลการเข้างานและการลา
4. ปฏิทินวันหยุด
5. PDPA consent flow (มีการเก็บรูปเซลฟี่และตำแหน่ง)
