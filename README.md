# TeachSchedule — ระบบตารางสอนอาจารย์ (รองรับหลาย site/สาขา)

ระบบบริหารจัดการตารางสอน การเช็คอิน-เช็คเอาต์ การลา และการรับรองเวลาของอาจารย์ ออกแบบให้เป็นระบบปิดใช้งานภายในองค์กร
(ผู้ดูแลระบบสร้างบัญชีให้เท่านั้น ไม่มีสมัครสมาชิกเอง) รองรับตั้งแต่องค์กรเดียวไซต์เดียว ไปจนถึงองค์กรที่มีอาจารย์หลายคน
กระจายกันไปประจำหลาย site/สาขา — ทุกอย่างที่เป็น "ข้อมูลเฉพาะขององค์กร" (สาขาวิชา, รายวิชา, ห้อง/อาคาร, ภาคเรียน,
จุดเช็คอิน, ใครประจำ site ไหน) จัดการได้เองผ่านหน้าเว็บ ไม่ต้องแก้โค้ดหรือ deploy ใหม่

## ฟีเจอร์หลัก

- **ระบบสมาชิกแบบปิด** — สิทธิ์ Admin / Member (อาจารย์) แยกกัน (NextAuth + role ใน JWT), ผู้ดูแลระบบสร้างบัญชีให้
  พร้อมสุ่มรหัสผ่านชั่วคราว, บังคับตั้งรหัสผ่านใหม่ตอน login ครั้งแรก, ป้องกัน brute-force ด้วยการล็อกบัญชีชั่วคราว
  หลังพยายามผิดหลายครั้ง
- **Dashboard** แยกมุมมอง Admin / อาจารย์
- **ตารางสอน** — ปฏิทินแบบเวลาอิสระ (ไม่ใช่คาบตายตัว) สไตล์ MS Teams, อาจารย์ดูของตัวเอง/Admin จัดการได้ทั้งหมด
  พร้อมตรวจจับการจองซ้ำซ้อน (ทั้งฝั่งอาจารย์และห้อง)
- **เช็คอิน/เช็คเอาต์ตามตำแหน่ง (GPS geofence)** — อาจารย์แต่ละคนมี **site ประจำ** ของตัวเอง (กำหนดโดย Admin ในหน้า
  จัดการผู้ใช้) เช็คอิน/เช็คเอาต์ต้องทำภายในรัศมีของ site นั้นเท่านั้น ไม่มี site ประจำ = เช็คอิน/เช็คเอาต์ไม่ได้
  จนกว่า Admin จะกำหนดให้ (กันไม่ให้เช็คอินจาก "ที่ไหนก็ได้" โดยไม่ตั้งใจ)
- **จุดเช็คอิน-เช็คเอาต์ (`CampusLocation`)** — Admin เพิ่ม/แก้ไข/ลบ site ได้เองผ่านแผนที่ (Leaflet + OpenStreetMap
  ฟรี ไม่ใช้ API key) พร้อมค้นหาชื่อสถานที่ผ่าน Google Places API (แม่นยำกว่า OpenStreetMap สำหรับชื่อสถานที่ไทย
  อยู่ในโควตาฟรีรายเดือน) หรือคลิกปักหมุด/ลากปรับตำแหน่งเอง วงกลมสีเขียวแสดงขอบเขตรัศมีแบบเรียลไทม์
- **ยื่นคำขอลา** + workflow อนุมัติ (รองรับประเภทการลาตาม พ.ร.บ. คุ้มครองแรงงาน ครบทุกประเภท)
- **ขอรับรองเวลา** + workflow อนุมัติ — ใช้เมื่อลืมเช็คอิน/เช็คเอาต์จริง บันทึกแยกจากเช็คอินผ่าน GPS จริง
- **แผนการสอน** — อาจารย์อัปโหลดไฟล์ (PDF/Word/PowerPoint) ต่อวิชาที่สอน, Admin ตรวจสอบ/อนุมัติ/ส่งกลับแก้ไข
- **ข้อมูลหลัก (Master Data)** — สาขาวิชา, รายวิชา, ห้อง/อาคาร (ผูกกับ site ได้), ภาคเรียน — Admin จัดการเองทั้งหมด
- **รายชื่ออาจารย์** — เห็น site ประจำ, ภาควิชา, สถานะเช็คอินวันนี้ ของอาจารย์ทุกคนในหน้าเดียว
- **สองภาษา (TH/EN)** สลับได้จากเมนู, **Light/Dark mode**, ติดตั้งเป็น PWA บนมือถือได้ (หน้าจอโฮม, session อยู่ได้นาน
  90 วันไม่ต้อง login ซ้ำบ่อยๆ)

## เริ่มต้นใช้งาน

**สิ่งที่ต้องมี:** Node.js 20+, PostgreSQL (local ผ่าน Docker หรือใช้ Railway/Neon ก็ได้)

```bash
npm install
cp .env.example .env      # แก้ DATABASE_URL, NEXTAUTH_SECRET, GOOGLE_PLACES_API_KEY ให้เป็นของจริง
npx prisma migrate dev --name init   # สร้างตารางในฐานข้อมูล
npm run prisma:seed                  # ใส่ข้อมูลตัวอย่าง (อาจารย์/วิชา/ห้อง/ตารางสอน)
npm run dev
```

### การสร้างบัญชีผู้ใช้ (ระบบปิด — ไม่มีสมัครสมาชิกเอง)

เพราะเป็นระบบใช้ภายในองค์กร จึง**ไม่มีหน้าสมัครสมาชิกสาธารณะ** — ผู้ดูแลระบบ (role `ADMIN`) เป็นคนสร้างบัญชีให้อาจารย์แต่ละคน
ผ่านหน้า **"จัดการผู้ใช้"** ในเมนู Admin (`/admin/users`) โดยกรอกชื่อ + อีเมล + ภาควิชา + **site ประจำ** + บทบาท
ระบบจะสุ่มรหัสผ่านชั่วคราวให้ แสดงบนหน้าจอครั้งเดียว (ผู้ดูแลระบบต้องคัดลอกไปแจ้งเจ้าตัวเอง เช่น พูดหรือส่ง LINE —
ไม่มีการส่งอีเมลใดๆ ในระบบนี้) ผู้ใช้จะถูกบังคับให้ตั้งรหัสผ่านใหม่ทันทีที่ login ครั้งแรก (`mustChangePassword`)
ถ้าอาจารย์ลืมรหัสผ่านทีหลัง ผู้ดูแลระบบกด "รีเซ็ตรหัสผ่าน" ในหน้าเดียวกันเพื่อออกรหัสผ่านชั่วคราวใหม่ได้ทันที
(ทำหน้าที่แทน "ลืมรหัสผ่าน" แบบไม่ต้องพึ่งอีเมล)

**site ประจำของอาจารย์แต่ละคนสำคัญมาก** — เป็นตัวกำหนดว่าเช็คอิน/เช็คเอาต์ของคนนั้นต้องอยู่ที่ไหน ถ้ายังไม่กำหนด
อาจารย์คนนั้นจะเช็คอิน/เช็คเอาต์ไม่ได้เลย (ระบบแจ้งเตือนชัดเจน ไม่ปล่อยให้เช็คอินจากที่ไหนก็ได้แบบเงียบๆ) ตั้งได้ตอน
สร้างบัญชีใหม่ หรือแก้ไขทีหลังได้ตลอดจาก dropdown ในหน้าจัดการผู้ใช้ — ต้องมีจุดเช็คอิน (`/admin/locations`) อย่างน้อย
1 จุดก่อนถึงจะเลือกได้

เปิด http://localhost:3000 แล้วเข้าสู่ระบบด้วยบัญชีทดสอบ

> บัญชี/รหัสผ่านสำหรับทดสอบดูได้ใน `prisma/seed.ts` (ไม่ commit ไว้ใน README เพราะ repo นี้อาจเป็น public)
> ก่อน deploy จริงหรือแชร์ repo นี้กับคนอื่น ให้เปลี่ยนรหัสผ่านที่ seed ไว้ และอีเมลตัวอย่างในนั้นด้วย

## ตั้งค่า Postgres แบบเร็วด้วย Docker

```bash
docker run --name teachschedule-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=webmanagement -p 5432:5432 -d postgres:16
```
แล้วใช้ `DATABASE_URL="postgresql://postgres:postgres@localhost:5432/webmanagement"` ใน `.env`

## ตัวแปรสภาพแวดล้อม (`.env`)

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `DATABASE_URL` | connection string ของ PostgreSQL |
| `NEXTAUTH_SECRET` | เข้ารหัส session/JWT — สร้างด้วย `openssl rand -base64 32` |
| `NEXTAUTH_URL` | URL ของเว็บ (เช่น `http://localhost:3000` ตอน dev) |
| `GOOGLE_PLACES_API_KEY` | ค้นหาชื่อสถานที่ในหน้าจุดเช็คอิน (`/admin/locations`) ผ่าน Google Places API — ต้องมี Google Cloud project ที่เปิด billing + เปิดใช้ "Places API (New)" อยู่ในโควตาฟรีรายเดือนที่ปริมาณการใช้งานของแอปนี้ (ไม่มีค่านี้ก็ยังใช้งานได้ แค่ค้นหาชื่อสถานที่ไม่ได้ ต้องกรอกพิกัดเองหรือคลิกบนแผนที่แทน) |

## จุดที่ควรรู้ก่อนทดสอบเช็คอิน

1. หน้าเช็คอินขอสิทธิ์ตำแหน่ง (Geolocation) จริงจากเบราว์เซอร์
2. ต้องมีจุดเช็คอิน (`CampusLocation`) อย่างน้อย 1 จุดที่ `/admin/locations` — พิกัดตัวอย่างที่ seed ไว้เป็นพิกัดสมมติ
   แก้เป็นพิกัดจริงของสถานที่ก่อนทดสอบ ไม่งั้นจะเช็คอินไม่ผ่านเพราะอยู่นอกรัศมีเสมอ
3. **ต้องกำหนด site ประจำให้อาจารย์แต่ละคนที่ `/admin/users` ด้วย** — ไม่มี site ประจำ = เช็คอิน/เช็คเอาต์ไม่ได้เลย
   ไม่ว่าจะยืนอยู่ตรงไหนก็ตาม (ดู `getExpectedSite` ใน `src/lib/geo.ts`)

## โครงสร้างโปรเจกต์

```
prisma/schema.prisma       โมเดลข้อมูลทั้งหมด (User, CampusLocation, Room, Schedule, Attendance, LeaveRequest, ...)
prisma/seed.ts             ข้อมูลตัวอย่างสำหรับทดสอบ
src/lib/auth.ts            การตั้งค่า NextAuth (Credentials + role ใน session + session 90 วันสำหรับ PWA)
src/lib/geo.ts             getExpectedSite() หา site ประจำของอาจารย์ + คำนวณระยะทาง/ตรวจสอบ geofence
src/lib/geocode.ts         ค้นหาชื่อสถานที่ผ่าน Google Places API (ใช้ในหน้าจุดเช็คอิน)
src/lib/mapConstants.ts    ค่าตกแต่ง/พฤติกรรมที่ใช้ร่วมกันของแผนที่ทุกจุดในระบบ (ไอคอน, สี, ซูม, ฯลฯ)
src/lib/i18n/              ข้อความสองภาษา (TH/EN) ทั้งหมดของระบบ
src/actions/users.ts       Admin สร้าง/รีเซ็ตรหัสผ่าน/กำหนด site ประจำผู้ใช้ + ผู้ใช้ตั้งรหัสผ่านใหม่เอง
src/actions/*.ts           Server Actions ของแต่ละโมดูล (attendance, leave, attest, schedule, locations, rooms, ...)
src/app/(app)/admin/users       หน้า Admin จัดการผู้ใช้ (สร้างบัญชี/รีเซ็ตรหัสผ่าน/กำหนด site ประจำ)
src/app/(app)/admin/locations   หน้า Admin จัดการจุดเช็คอิน (แผนที่ + ค้นหาสถานที่)
src/app/(app)/admin/master-data หน้า Admin จัดการสาขาวิชา/รายวิชา/ห้อง/ภาคเรียน
src/app/(app)/checkin           หน้าเช็คอิน-เช็คเอาต์ (มุมมองอาจารย์ + ภาพรวมของ Admin)
src/app/(app)/teachers          รายชื่ออาจารย์ทั้งหมด (Admin)
src/app/(app)/*                 หน้าเว็บหลังล็อกอินอื่นๆ แยกตามเมนู
src/components/*                UI components ที่ใช้ร่วมกัน (LocationPickerMap, LocationsMap, UserManagement, ...)
```

## ขั้นตอนถัดไปที่แนะนำ

1. กำหนด site ประจำให้อาจารย์ทุกคนที่ `/admin/users` (จำเป็นก่อนเช็คอิน/เช็คเอาต์จะใช้งานได้จริง)
2. ต่อ LINE Notify ตอนอนุมัติ/ปฏิเสธคำขอ และตอนแก้ตารางสอน
3. รายงาน/Export ข้อมูลการเข้างาน
4. ปฏิทินวันหยุด
5. PDPA consent flow

รายละเอียดการเปลี่ยนแปลงในแต่ละรอบ ดูที่ [`CHANGELOG.md`](./CHANGELOG.md)
